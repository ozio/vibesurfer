# Theme Contract Trial

`editorial` is the first theme implemented as a consumer of the documented authoring API. The trial deliberately changed no React component, shared component stylesheet, chrome recipe, navigation recipe, store, or runtime adapter.

Open **Browser / BrowserShell / Playground** and select Editorial to exercise every toolbar axis. **Browser / BrowserShell / Editorial** is the fixed canonical baseline used by **Foundation / Theme matrix**, where the same fixture stays visible beside every established implementation.

## Scope

The theme exercises a visual direction not represented by the original set:

- serif display typography with sans UI and monospace evidence roles;
- light and dark ink-and-paper palettes;
- almost-square controls and flat tactile surfaces;
- double-rule chrome dividers and an explicit active-tab rule;
- editorial portal composition using the existing named decorative slots;
- the standard chrome and navigation recipes in both horizontal and vertical tab layouts.

All visual implementation lives in `src/styles/themes/editorial/theme.css`. Content, generation instructions, preset copy, search behavior, native window radius, and canonical stories are registry data.

Two ideas remain candidates rather than contract additions: a semantic chrome-divider token and an active-tab-indicator token. Editorial is the only implementation that needs their unusual width and style, so narrow selectors are clearer until another theme repeats the decision.

## Authoring footprint

The required edits for a complete theme are intentionally explicit:

1. Generate `themes/<id>/theme.css` with `theme:scaffold` and keep one complete unqualified root.
2. Register the ID and browser experience in the frontend registry.
3. Add generation-world and font instructions to the worker registry.
4. Add the profile preset mapping and the canonical stylesheet import.
5. Add a canonical BrowserShell story and matrix story ID.
6. Choose a native window radius and an existing structural recipe.
7. Run the contract validator, typecheck, interaction/a11y tests, static build, and packaged-app smoke.

This is the minimum safe workflow for a future browser-theme-authoring skill. The skill should stop and report a contract gap if a requested visual requires editing shared components, inventing positional selectors, or silently adding a new structural recipe.

## Acceptance evidence

The trial is successful only while these properties stay true:

- `BROWSER_THEME_IDS`, toolbar items, presets, worker schema, worker registry, canonical stories, and CSS imports contain the same ordered set;
- `theme:validate` reports five themes and a complete 47/24 token contract;
- the scaffold regression test passes;
- Editorial is present in the visual matrix and its light/dark token stories keep blocking a11y behavior;
- `rg` finds no Editorial branch in shared component CSS or React components.
